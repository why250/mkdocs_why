I2C 和 SPI 是嵌入式系统中最常用的两种**同步串行通信协议**，它们都用于在单个主板上的芯片之间进行短距离通信，比如单片机（MCU）与传感器、存储器、ADC/DAC等外设之间。

尽管它们的目的相似，但实现方式、速度和应用场景却有很大不同。

---

### **SPI (Serial Peripheral Interface / 串行外设接口)**

可以把它想象成一条**高速、全双工的“私密电话线”**。

#### **1. 核心概念**

SPI 是一种**主从（Master-Slave）**架构的通信协议。通信总是由主设备（通常是MCU）发起。它速度非常快，并且支持**全双工**通信，意味着主设备和从设备可以同时发送和接收数据。

#### **2. 工作原理与引脚**

SPI 通信通常需要 **4 根线**：

*   **SCLK (Serial Clock):** 串行时钟。由 Master 产生，用来同步数据传输，是整个通信的“心跳”。
*   **MOSI (Master Out Slave In):** 主出从入。Master 通过这条线向 Slave 发送数据。
*   **MISO (Master In Slave Out):** 主入从出。Slave 通过这条线向 Master 发送数据。
*   **CS / SS (Chip Select / Slave Select):** 片选信号。由 Master 控制。当 Master 想和某个 Slave 通信时，会先将对应 Slave 的 CS 线拉低（变为有效电平）。只有被选中的 Slave 才会响应 SCLK 和 MOSI 上的信号。

**通信流程：**
1.  Master 将想要通信的那个 Slave 的 **CS** 线拉低。
2.  Master 在 **SCLK** 线上产生时钟脉冲。
3.  在每个时钟脉冲，Master 将一位数据推送到 **MOSI** 线上，同时从 **MISO** 线上读取一位数据。
4.  通信结束后，Master 将 **CS** 线拉高，结束本次通信。



#### **3. 优缺点**

| 优点 👍                                         | 缺点 👎                                                 |
| ----------------------------------------------- | ------------------------------------------------------- |
| **速度非常快**，通常可达几十 Mbps。             | **需要更多引脚**，每个从设备都需要一根独立的 CS 线。      |
| **全双工通信**，数据可以同时收发，效率高。      | **没有内置的寻址机制**，完全依赖 CS 线来选择从设备。    |
| **协议简单**，硬件实现容易，软件开销小。        | **没有从设备应答（ACK）机制**，Master 不知道数据是否被成功接收。 |
| 灵活性高，数据位数和传输格式可以自定义。        | **没有标准化的多主控支持**，通常只有一个 Master。         |

### **I2C (Inter-Integrated Circuit / 集成电路总线)**

可以把它想象成一个**“电话会议”或“派对热线”**，所有设备都在同一条线上，通过“喊名字”来交流。

#### **1. 核心概念**

I2C 是一种**多主控、多从设备**的总线型协议。它只需要两根线就可以连接大量的设备。通信是**半双工**的，即在同一时刻，数据只能单向传输。

#### **2. 工作原理与引脚**

I2C 通信只需要 **2 根线**：

*   **SDA (Serial Data):** 串行数据线。用于双向传输数据。
*   **SCL (Serial Clock):** 串行时钟线。通常由 Master 产生，同步数据传输。

**关键特性：**
*   **寻址机制：** 每个连接到总线上的从设备都有一个唯一的7位（或10位）地址。Master 发起通信时，首先会发送一个“**起始信号**”，然后广播它想找的那个从设备的地址。
*   **应答机制 (ACK/NACK):** 地址匹配的从设备在接收到自己的地址后，会发送一个“**应答位 (ACK)**”给 Master，告诉它“我在线，准备好了”。如果 Master 发送地址后没有收到 ACK，就知道该设备不存在或无响应。
*   **上拉电阻：** SDA 和 SCL 两条线路上必须接**上拉电阻**。这是因为 I2C 设备采用“开漏”或“开集”输出，它们只能将总线拉低到0，不能主动输出高电平。当所有设备都不操作时，上拉电阻会将总线拉到高电平。

**通信流程：**
1.  Master 发送一个 **起始信号 (Start Condition)**。
2.  Master 在 SDA 线上发送 **7位从设备地址** 和 **1位读/写控制位**。
3.  总线上所有 Slave 监听地址，匹配的 Slave 回复一个 **ACK**。
4.  Master（或 Slave，取决于读写操作）开始传输8位数据。
5.  每传输完一个字节，接收方都会回复一个 **ACK**。
6.  通信结束后，Master 发送一个 **停止信号 (Stop Condition)**，释放总线。



#### **3. 优缺点**

| 优点 👍                                               | 缺点 👎                                             |
| --------------------------------------------------- | --------------------------------------------------- |
| **极少的引脚**，仅需 2 根线即可连接众多设备。         | **速度相对较慢**，标准模式100kbps，快速模式400kbps。 |
| **内置寻址机制**，可以在总线上轻松添加或移除设备。    | **半双工通信**，数据不能同时收发。                  |
| **有应答（ACK）机制**，通信更可靠，Master 知道从设备的状态。 | **协议更复杂**，有起始/停止/应答等状态，软件开销更大。   |
| **支持多主控**，允许多个 Master 控制总线（有仲裁机制）。 | **硬件上需要上拉电阻**，总线电容会限制设备数量和通信距离。 |

### **总结与对比**

| 特性             | SPI (私密电话线)                        | I2C (电话会议)                                  |
| ---------------- | --------------------------------------- | ----------------------------------------------- |
| **引脚数量**     | **多 (4根起步)**，每个从设备额外增加1根CS线 | **少 (仅2根)**，与设备数量无关                |
| **速度**         | **快** (>>1 Mbps)                         | **慢** (<1 Mbps)                                |
| **通信模式**     | **全双工** (可同时收发)                   | **半双工** (同一时间只能单向传输)               |
| **设备角色**     | 严格的**主从**模式                      | **多主控，多从设备**                            |
| **从设备选择**   | 通过独立的 **CS 片选线**                | 通过总线广播 **设备地址**                       |
| **可靠性**       | **无**内置应答机制                      | **有** ACK/NACK 应答机制                        |
| **应用场景**     | 高速数据流，如 **SD卡、显示屏、高速ADC/DAC** | 连接大量低速外设，如 **各种传感器、EEPROM、实时时钟** |

**一句话总结：**

*   当你需要**高速率**、**点对点**（或点对少数几个点）的数据传输，并且不介意多用几个引脚时，选择 **SPI**。
*   当你需要连接**很多设备**、**引脚资源紧张**，并且对速度要求不高时，选择 **I2C**。
